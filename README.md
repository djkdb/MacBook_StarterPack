# 맥북 스타터팩 (MacBook Starter Pack)

맥북을 처음 산 사람을 위한 **인터랙티브 퀘스트형 가이드**입니다.

설명서를 읽는 방식이 아닙니다. 브라우저가 실제 키 입력과 트랙패드 제스처를 감지해서,
**직접 눌러야 다음 단계로 넘어갑니다.**

- 12개 챕터 · 132개 퀘스트 · 총 2610 XP
- 레벨과 칭호(맥린이 → 맥북 마스터), 챕터별 배지
- 진행 상황은 브라우저에 자동 저장 (`localStorage`)
- 인쇄 가능한 단축키 치트시트 내장
- **macOS 26 Tahoe 기준**입니다 (아래 [기준 macOS 버전](#기준-macos-버전) 참고)
- Apple의 디자인 언어로 만들었습니다 (아래 [디자인](#디자인) 참고)
- 의존성 없음 — HTML/CSS/JS 파일 몇 개가 전부입니다

## 실행하기

가장 간단한 방법은 그냥 파일을 여는 것입니다.

```bash
open index.html
```

로컬 서버로 띄우고 싶다면:

```bash
python3 -m http.server 8000
# http://localhost:8000
```

다른 사람에게 링크로 주고 싶다면 GitHub Pages를 켜면 됩니다.
저장소 **Settings → Pages → Source: Deploy from a branch** 에서 브랜치와 `/ (root)` 를
고르면 별도 빌드 없이 바로 배포됩니다. 정적 파일이라 설정할 게 없습니다.

> 판정 기능은 **macOS의 브라우저에서 열어야** 정상 동작합니다.
> 맥이 아닌 기기에서 열면 시작 화면에 안내가 표시되고, 내용은 그대로 볼 수 있습니다.

## 기준 macOS 버전

이 가이드는 **macOS 26 Tahoe** 기준으로 쓰였습니다.
시작 화면과 푸터에도 그렇게 표시됩니다.

버전별로 분기하지 않은 것은 의도된 선택입니다. 132개 퀘스트 중 버전에 따라 실제로
갈리는 것은 10개 남짓인데, 그 10개 때문에 전체 콘텐츠에 버전 축을 하나 더 만들면
나머지 100여 개가 전부 중복되고 유지보수가 배로 늘어납니다. 새 맥북을 사면 최신 macOS가
설치되어 온다는 점도 고려했습니다.

macOS 26에서 이전 버전과 크게 달라진 지점은 다음과 같고, 본문은 전부 26 기준으로
쓰여 있습니다.

| 항목 | macOS 26에서의 변화 |
|------|--------------------|
| Launchpad | **제거됨.** 네 손가락 오므리기는 Spotlight의 "응용 프로그램" 화면을 엽니다 |
| Spotlight | ⌘1~⌘4 로 앱 / 파일 / 빠른 작업 / **클립보드 기록** 전환 |
| 전화 앱 | Mac에 처음 추가. 아이폰의 최근 통화·즐겨찾기·음성사서함이 넘어옵니다 |
| 메뉴 막대 | 기본이 완전 투명. "메뉴 막대 배경 표시"로 되돌릴 수 있습니다 |
| 확인되지 않은 앱 | ctrl-클릭으로 여는 우회가 **없어졌습니다.** 시스템 설정 > 개인정보 보호 및 보안 에서 "그래도 열기" + 관리자 암호 |
| 배터리 충전 한도 | 80~95% 상한 설정은 **26.4부터**입니다. 그 이전 26.x에는 없습니다 |
| Liquid Glass | 창·메뉴가 유리처럼 비칩니다. 시스템 설정 > 외관 에서 "색조"로 줄일 수 있습니다 |
| 제어 센터 | 아이폰처럼 항목을 추가·삭제·재배열하고 메뉴 막대로 끌어낼 수 있게 됐습니다 |
| 폴더 사용자화 | 폴더에 색·기호·이모지를 입힐 수 있습니다 (폴더 우클릭 > 폴더 사용자화) |

기준 버전 문자열은 `quests.js` 의 `TARGET_OS` 한 곳에만 있습니다. 나중에 macOS 27이
나오면 이 상수와 위 아홉 항목만 손보면 됩니다.

## 레벨과 배지

칭호는 13단계이고, **각 단계의 기준 XP를 챕터 완주 시점의 누적 XP에 정확히 맞춰
두었습니다.** 챕터를 하나 끝낼 때마다 정확히 한 번 레벨이 오릅니다.

| Lv | 칭호 | 필요 XP | 올라가는 시점 |
|---:|------|--------:|---------------|
| 1 | 🐣 맥린이 | 0 | 시작 |
| 2 | 🔰 수식어 견습생 | 75 | 1챕터 완주 |
| 3 | ⌨️ 단축키 수련생 | 200 | 2챕터 완주 |
| 4 | ✍️ 텍스트 편집자 | 385 | 3챕터 완주 |
| 5 | 🖐️ 트랙패드 유단자 | 645 | 4챕터 완주 |
| 6 | 🔍 Spotlight 술사 | 775 | 5챕터 완주 |
| 7 | 🪟 창 정리의 달인 | 980 | 6챕터 완주 |
| 8 | 📸 스크린샷 저격수 | 1125 | 7챕터 완주 |
| 9 | 🧭 Finder 항해사 | 1490 | 8챕터 완주 |
| 10 | 📦 설치 관문 통과 | 1670 | 9챕터 완주 |
| 11 | 🔗 생태계 연결자 | 2040 | 10챕터 완주 |
| 12 | 💾 용량 관리인 | 2240 | 11챕터 완주 |
| 13 | 🏆 맥북 마스터 | 2610 | 전부 완주 (만점) |

흔한 방식인 "100 XP마다 레벨업" 같은 균등 분할을 쓰지 않은 이유는, 그러면 챕터 중간
애매한 지점에서 올라가서 성취감이 흩어지기 때문입니다. 지금은 마지막 퀘스트를 깨는
순간 **챕터 완주 + 배지 획득 + 레벨업**이 한꺼번에 일어납니다.

단계별 XP 폭이 고르지 않은 것(125~370)은 챕터 분량을 그대로 반영한 결과입니다.
대신 2·3단계를 짧게 두어, 처음 시작한 사람이 10분 안에 두 번 레벨업을 경험하게 했습니다.

퀘스트 개별 XP는 난이도에 따라 10~30이고, `boss: true` 인 퀘스트만 50입니다.
현재 보스는 둘 다 실제 붙여넣기로 검증되는 것들입니다 — ⌃⇧⌘4 클립보드 캡처(`ss-boss`),
아이폰 사진을 유니버설 클립보드로 넘기기(`eco-clip-photo`).

배지는 챕터당 하나로, **건너뛴 퀘스트가 하나라도 있으면 주지 않습니다.**
(진행률에는 반영되지만 배지는 전부 클리어해야 합니다)

## 디자인

Apple의 웹 디자인 언어를 그대로 따랐습니다. 게임적인 요소(XP·레벨·배지)는 유지하되,
표현은 전부 Apple의 문법 안에서 하는 것이 목표였습니다.

### 원칙

- **인터랙션 색은 Action Blue(`#0066cc`) 하나뿐입니다.** 링크, 필 버튼, 포커스 링, 진행
  표시줄이 전부 이 색입니다. 두 번째 브랜드 색은 존재하지 않습니다.
- **장식용 그라디언트가 없습니다.** 분위기는 색면(色面) 자체가 만듭니다.
- **그림자는 시스템 전체에서 딱 하나** — 표면 위에 놓인 "제품 이미지"에만
  `rgba(0,0,0,.22) 3px 5px 30px` 를 씁니다. 카드·버튼·텍스트에는 그림자가 없습니다.
  이 프로젝트에서 "제품"에 해당하는 것은 **키캡**과 **챕터 아이콘**입니다.
- **밝은 타일 ↔ 어두운 타일의 색 전환 자체가 섹션 구분선입니다.** 테두리도, 여백도,
  둥근 모서리도 쓰지 않습니다. 홈은 이 타일이 세로로 쌓인 구조입니다.
- **본문은 16px이 아니라 17px** 입니다. 디스플레이 크기에는 음수 자간(-0.28 ~ -0.374px)을
  넣어 Apple 특유의 조밀한 헤드라인 리듬을 만듭니다.
- **weight 500은 쓰지 않습니다.** 사다리는 300 / 400 / 600 / 700 입니다.
- 버튼을 누를 때는 시스템 전역 미세 인터랙션인 `transform: scale(0.95)` 가 걸립니다.

### 서체

```
"SF Pro Display" / "SF Pro Text", -apple-system, BlinkMacSystemFont, system-ui,
"Apple SD Gothic Neo", "Pretendard", "Noto Sans KR", sans-serif
```

macOS·iOS에서는 `-apple-system` 이 진짜 SF Pro로 해석되고, 한글은 Apple SD Gothic Neo가
이어받습니다. 글꼴 대체는 글자 단위로 일어나므로 영문은 SF Pro, 한글은 SD Gothic Neo로
자연스럽게 섞입니다. 웹폰트를 내려받지 않으므로 로딩도 없습니다.

### 구조

| 영역 | 사양 |
|------|------|
| 글로벌 내비 | 44px, 순수 블랙(`#000`), 12px 내비 링크 |
| 서브 내비 | 52px, 파치먼트 80% + `backdrop-filter: saturate(180%) blur(20px)` |
| 진행 표시줄 | 서브 내비 아래 가장자리에 붙는 2px 실선 |
| 홈 | 풀블리드 타일 스택 — 흰색 / 파치먼트(`#f5f5f7`) / 근접 블랙(`#272729`·`#2a2a2c`·`#252527`) 교차 |
| 퀘스트 | 최대 780px 단일 칼럼 + 왼쪽 조용한 레일 (833px 이하에서 레일 숨김) |
| 푸터 | 파치먼트, 64px 패딩 |

모서리 반경은 문법별로 고정입니다 — 유틸리티 8px, 카드 18px, 액션·칩·입력은 필(pill).
그 사이의 임의값은 쓰지 않습니다.

### 의도적으로 확장한 부분

원본 디자인 시스템에 없지만 학습 도구라서 필요했던 것이 하나 있습니다.

**정답 / 오답 표시색** (`--state-pass: #248a3d`, `--state-fail: #d70015`).
퀴즈에서 맞았는지 틀렸는지는 Action Blue만으로는 전달되지 않습니다.
Apple의 시스템 색을 가져와 **의미 전달에만** 쓰고, 링크·버튼·포커스 같은
인터랙션 신호에는 절대 쓰지 않았습니다. "클릭 가능함"을 뜻하는 색은 여전히 Action Blue
하나뿐이라는 원칙은 지켜집니다.

축하 효과(색종이)도 챕터 완료와 졸업이라는 드문 순간에만, Action Blue 계열 색으로만
떨어집니다.

### 수식어 표기 순서

Apple의 공식 순서는 **⌃ → ⌥ → ⇧ → ⌘** 입니다. `⌘⇧Z` 가 아니라 `⇧⌘Z` 가 맞습니다.
`engine.js`의 `symbols()` / `keycaps()` 가 이 순서로 렌더링하며, `quests.js`의 본문 표기도
전부 여기에 맞춰져 있습니다. 새 콘텐츠를 쓸 때도 이 순서를 지켜주세요.

## 파일 구조

```
index.html    화면 뼈대 (글로벌 내비 · 서브 내비 · 본문 · 푸터)
styles.css    디자인 토큰과 전체 스타일 (반응형, 치트시트 인쇄용 포함)
quests.js     모든 콘텐츠 — 챕터·퀘스트·랭크·배지·치트시트
engine.js     판정 엔진 — 키/제스처/클립보드 감지
app.js        진행 상태, 화면 전환, 저장
```

색·간격·서체·모서리는 전부 `styles.css` 최상단 `:root` 의 CSS 변수로 정의되어 있습니다.
디자인을 바꾸려면 그 블록만 손대면 됩니다.

콘텐츠와 판정 로직이 분리되어 있어서, **퀘스트를 추가하려면 `quests.js`만 건드리면 됩니다.**

## 판정 방식

`quests.js`의 각 퀘스트는 `check.t` 로 판정 방식을 고릅니다.

| `check.t` | 판정 내용 |
|-----------|-----------|
| `mod` | 수식어 키 하나를 누름 (`keydown`) |
| `allmods` | ⌃⌥⇧⌘ 를 동시에 누름 |
| `combo` | 단축키 조합. `spec:'cmd+shift+z'` 형식 |
| `editor` | 연습용 텍스트 상자의 편집 결과·커서 위치 비교 |
| `scroll` | 지정한 축의 휠 델타 누적 (두 손가락 스크롤/스와이프) |
| `pinch` | `ctrlKey`가 붙은 `wheel`(Chrome·Firefox) 또는 `gesturechange`(Safari) |
| `contextmenu` | 두 손가락 클릭 = 보조 클릭 |
| `pasteImage` | 붙여넣은 클립보드에 이미지가 들어 있는지 확인 |
| `pasteText` | 붙여넣은 클립보드의 텍스트를 확인 (유니버설 클립보드) |
| `emoji` | 입력값에 이모지가 포함되었는지 확인 |
| `answer` | 정답 입력. `accept`(정답 목록, 공백·쉼표 무시) 또는 `range`(숫자 범위) |
| `keyrepeat` | 키를 꾹 눌렀을 때의 **반복 간격을 실측**. `ms` 보다 빠르면 통과 |
| `nfd` | 붙여넣은 한글이 자모로 쪼개져 있는지(NFD) 확인하고 글자 수를 비교해 보여줌 |
| `blur` | 브라우저가 포커스를 잃었다 돌아옴 |
| `quiz` / `manual` | 객관식 / 직접 해보고 체크 |

`answer`의 `range` 는 **기기마다 답이 다른 질문**을 위한 것입니다. 예를 들어
"저장 공간이 몇 GB 남았나요?"는 정답을 미리 알 수 없지만, 그럴듯한 범위 안의 숫자를
요구하는 것만으로 "설정을 실제로 열어봤다"를 강제할 수 있습니다.

`keyrepeat` 과 `nfd` 는 **시스템 설정과 OS 동작을 브라우저가 실제로 관찰할 수 있는**
드문 경우라서 따로 만들었습니다.

- `keyrepeat` — 키를 누르고 있으면 OS가 정한 간격으로 `keydown`(`e.repeat === true`)이
  들어옵니다. 그 간격의 중앙값을 재면 "키 반복 속도" 설정을 실제로 올렸는지 알 수
  있습니다. 기본값은 90ms 안팎, 가장 빠르게 두면 15ms 근처까지 내려갑니다.
  첫 반복에는 "반복 지연 시간"이 섞여 있어 계산에서 버립니다.
- `nfd` — macOS는 파일 이름의 한글을 자음·모음으로 쪼개서 보관합니다(NFD).
  Finder에서 복사한 이름을 붙여넣고 `text !== text.normalize('NFC')` 를 보면 그 사실이
  그대로 드러납니다. 화면에는 원본·NFC·NFD의 글자 수를 나란히 보여줍니다
  ("한글문서" → 11자 / 4자 / 11자). 한글 검사는 NFC로 정규화한 뒤에 해야 합니다.
  쪼개진 한글은 `가-힣` 이 아니라 조합용 자모(U+1100~)로 들어오기 때문입니다.

키 조합은 `e.key`가 아니라 **`e.code`로 판정**합니다. macOS에서 ⌥를 누른 채 글자를 치면
`e.key`가 특수문자(`˙`, `ø` 등)로 바뀌고, 한글 입력 상태에서도 값이 달라지기 때문입니다.

### 챕터마다 성격이 다릅니다

전수 점검해보면 판정 방식의 분포가 챕터별로 크게 다릅니다.

| 챕터 | 브라우저가 통과를 판정 | 성격 |
|------|----------------------|------|
| 1~3 (수식어·단축키·텍스트) | 27 / 27 | 실제로 눌러야만 넘어가는 구간 |
| 4~6 (트랙패드·Spotlight·창) | 19 / 31 | 제스처는 감지, 시스템 설정은 자가 체크 |
| 7~12 (스크린샷·Finder·앱설치·생태계·저장소·세팅) | 32 / 74 | 대부분 따라 하고 체크하는 구간 |

뒤로 갈수록 자동 판정이 줄어드는 것은 소재의 성격 때문입니다. 시스템 설정을 바꿨는지,
AirDrop을 보냈는지를 웹페이지가 알아낼 방법은 없습니다. 그래서 세 가지로 대응했습니다.

1. **감지할 수 있는 것은 최대한 감지합니다.** 예를 들어 "저장 공간이 몇 GB 남았나"는
   직접 열어보지 않으면 답할 수 없게 입력 판정으로 만들었고, "키 반복 속도"는 실제로
   반복 간격을 재서 설정을 바꾸지 않으면 통과되지 않게 했습니다.
2. **감지가 불가능하면 최소한 이해도라도 확인합니다.** 설정을 바꾸는 퀘스트 상당수는
   뒤에 퀴즈를 붙여, 틀리면 통과되지 않게 했습니다.
3. **홈 화면의 챕터 타일에 성격을 표시합니다.** "직접 눌러보며 익히는 챕터"인지
   "설정을 따라 하며 점검하는 챕터"인지 미리 알 수 있어서, 뒤쪽 챕터에서
   기대가 어긋나지 않습니다.

### 판정이 완벽하지 않은 부분 (알고 쓰세요)

브라우저가 볼 수 없는 것들이 있습니다. 해당 퀘스트는 정직하게 다른 방식으로 처리했습니다.

- **⌘Space(Spotlight), ⌃↑(미션 컨트롤), ⌥⌘esc(강제 종료), 네 손가락 오므리기(앱 목록)** 등은
  macOS가 가로채서 웹페이지까지 키 이벤트가 오지 않습니다. → `blur` 로 "화면을 다녀왔다"는
  사실만 확인합니다. 어떤 단축키를 썼는지까지는 구분하지 못합니다.
- **⇧⌘3 / ⇧⌘4 스크린샷**은 키 이벤트도, 포커스 변화도 발생하지 않습니다. → 직접 확인(`manual`)
  입니다. 다만 보스 퀘스트인 **⌃⇧⌘4(클립보드로 캡처)** 는 붙여넣기로 이미지를 실제로 검증합니다.
- **⌘`(같은 앱 창 전환)** 도 macOS가 직접 처리하므로 `manual` 입니다.
- 시스템 설정을 바꾸는 퀘스트(11·12챕터 등)는 대부분 감지할 수 없어 체크박스 방식입니다.
  예외가 **키 반복 속도**로, 여기만 설정 결과를 직접 측정할 수 있습니다.
- **앱 설치**(dmg 드래그, 확인되지 않은 앱 열기, 앱 삭제)는 브라우저 밖의 일이라
  전부 직접 확인입니다. 예외가 **한글 자모 분리**로, 붙여넣은 이름을 실제로 검사합니다.
- **연속성 기능**(AirDrop, Handoff, Sidecar, 유니버설 컨트롤 등)은 웹페이지가 볼 수 없는
  OS 기능이라 대부분 직접 확인입니다. 예외가 **유니버설 클립보드**로, 붙여넣기 이벤트를
  실제로 검사합니다. 다만 브라우저는 그 클립보드 내용이 *아이폰에서* 온 것인지 맥에서
  복사한 것인지 구분할 수 없습니다. "붙여넣기가 일어났고 내용이 있다"까지만 보장합니다.

`editor` 판정에는 `via` 옵션이 있어서, 마우스로 커서를 옮겨 우연히 통과하는 걸 막습니다.
지정한 단축키를 실제로 누른 경우에만 정답으로 인정합니다.

### 브라우저 기본 동작 차단

학습을 방해하는 기본 동작은 막아둡니다. 입력칸 **밖**에서 누른 ⌘ 조합은 `preventDefault`
처리되어, ⌘←로 뒤로 가버리거나 ⌘S로 저장 대화상자가 뜨는 일이 없습니다.
다만 ⌘R(새로고침), ⌘T, ⌘N, ⌘W, ⌘Q 는 탈출구로 남겨두었습니다.

## 진행 흐름

사용자가 막히거나 길을 잃지 않도록 정한 규칙들입니다.

- **순서를 강제하지 않습니다.** 어느 챕터에서 시작하든 됩니다.
- **모든 퀘스트에 건너뛰기가 있습니다.** 기기가 없거나 기능이 지원되지 않아
  진행이 막히는 일이 없도록 한 탈출구입니다. 건너뛴 퀘스트는 XP를 주지 않고,
  사이드바에 다른 표시로 남으며, 그 챕터의 배지도 나오지 않습니다.
- **이어하기는 "다음 할 일"로 데려갑니다.** 마지막으로 본 퀘스트가 이미 클리어된
  상태라면 끝난 화면을 다시 보여주지 않고 다음 미완료 퀘스트로 넘깁니다.
- **사이드바가 현재 위치를 따라갑니다.** 퀘스트가 132개라 레일이 화면보다 길어서,
  현재 퀘스트가 레일 밖으로 나가면 스스로 스크롤해 가운데로 옵니다.
- **클리어한 퀘스트를 다시 열어도 판정기는 살아 있습니다.** 반복 연습이 가능하되,
  성공 처리는 화면당 한 번만 일어나 XP가 중복 적립되지 않습니다.

진행 상황은 `localStorage` 의 `macbook-starterpack.v1` 키 하나에만 저장되고
어디로도 전송되지 않습니다. 초기화는 상단 검은 내비게이션 오른쪽의 **초기화** 입니다.

## 학습 순서

내용을 추가하다 보면 순서가 어긋나기 쉬워서, 다음 네 가지를 규칙으로 두고 있습니다.

1. **안내문(`how`)은 이미 배운 것만 요구합니다.** `how` 는 "지금 이대로 하세요"라는
   지시라서, 아직 안 나온 단축키를 쓰라고 하면 그 자리에서 막힙니다.
   (`tip` 이나 해설에서 뒤 챕터를 예고하는 것은 괜찮습니다)
2. **퀴즈에는 두 종류가 있고 서로 지켜야 할 것이 다릅니다.**
   제목에 "점검"이 붙는 **점검형**은 앞에서 배운 것만 물어야 하고,
   해설이 본체인 **교육형**은 새 지식을 가르쳐도 되지만 제목·부제가 답을 흘리면 안 됩니다.
3. **챕터는 실습으로 시작해 점검으로 끝냅니다.** 도입부가 퀴즈면 배우기도 전에 시험보는
   꼴이 됩니다. (설정을 먼저 열어보게 한 뒤 묻는 경우는 예외)
4. **챕터 안에서는 기본 조작 → 응용 → 설정 순으로 갑니다.**

`quests.js` 를 고친 뒤에는 아래로 한 번에 확인할 수 있습니다.

```bash
node -e "
const src=require('fs').readFileSync('quests.js','utf8');
const {CHAPTERS}=new Function(src+';return {CHAPTERS};')();
const ALL=[]; CHAPTERS.forEach((c,ci)=>c.quests.forEach(q=>{q._ci=ci; q._f=ALL.length; ALL.push(q);}));
const SC=/[⌃⌥⇧⌘]+(?:Space|Tab|[A-Z0-9]|←|→|↑|↓|⌫|,|\.)/g;
const strip=s=>(s||'').replace(/<[^>]+>/g,'');
const topic=q=>new Set(strip(q.sub).match(SC)||[]);
const first={}; ALL.forEach(q=>topic(q).forEach(s=>{ if(!(s in first)) first[s]=q._f; }));
ALL.forEach(q=>{
  const own=topic(q), used=new Set(strip((q.how||[]).join(' ')).match(SC)||[]);
  [...used].filter(s=>!own.has(s) && s in first && first[s]>q._f)
    .forEach(s=>console.log('전방 참조:', q.id, '가', s, '를 먼저 씁니다'));
});
CHAPTERS.forEach((c,i)=>{
  if(c.quests[0].check.t==='quiz' && !c.quests[0].how) console.log((i+1)+'장이 안내 없는 퀴즈로 시작');
  const l=c.quests.at(-1);
  if(l.check.t!=='quiz') console.log((i+1)+'장이 점검 없이 끝남');
});
"
```

## 퀘스트 추가하기

`quests.js`의 원하는 챕터 `quests` 배열에 객체를 하나 넣으면 끝입니다.

```js
{
  id: 'k-newtab',                 // 저장에 쓰이므로 고유해야 합니다
  title: '새 탭 열기',
  sub: '⌘T',                       // 단축키처럼 보이면 치트시트에 자동으로 실립니다
  xp: 10,                          // 보통 10~30, 보스만 50
  boss: true,                      // (선택) 보스 표시
  how: ['⌘ 를 누른 채 T 를 누르세요.'],   // 각 줄에 <b> 같은 태그를 써도 됩니다
  tip: '클리어한 뒤에 보여줄 한 줄 지식',
  check: { t: 'combo', spec: 'cmd+t' }
}
```

챕터를 통째로 추가한다면 `id` · `icon` · `title` · `tagline`(홈 타일 한 줄) ·
`intro`(첫 퀘스트 상단) · `quests` 가 필요하고, `BADGES` 에 같은 `id` 로 배지를
넣어주어야 합니다. 홈 타일의 명암 교차와 "직접 눌러보며 익히는 챕터 / 설정을 따라
하며 점검하는 챕터" 라벨은 자동으로 계산되므로 따로 손댈 것이 없습니다.

### XP를 바꿨다면 반드시 확인하세요

퀘스트를 추가하거나 XP를 조정하면 `RANKS` 의 기준값이 어긋납니다. 두 가지가 깨질 수
있는데, 둘 다 조용히 깨져서 눈치채기 어렵습니다.

1. 최고 랭크 기준이 총 XP보다 크면 **만점을 받아도 마지막 칭호에 도달할 수 없습니다.**
2. 랭크 기준이 챕터 경계와 어긋나면 **레벨업이 챕터 중간에서 일어납니다.**

아래를 붙여넣어 한 번에 확인할 수 있습니다. (실제로 1번은 개발 중에 한 번 걸렸습니다)

```bash
node -e "
const src=require('fs').readFileSync('quests.js','utf8');
const {CHAPTERS,RANKS}=new Function(src+';return {CHAPTERS,RANKS};')();
let cum=0; const bounds=[0];
CHAPTERS.forEach(c=>{ cum+=c.quests.reduce((s,q)=>s+q.xp,0); bounds.push(cum); });
const bad=RANKS.filter(r=>!bounds.includes(r.xp)).map(r=>r.name+'('+r.xp+')');
console.log('퀘스트', CHAPTERS.flatMap(c=>c.quests).length, '| 총 XP', cum);
console.log('최고 랭크 도달 가능:', cum>=RANKS.at(-1).xp ? 'OK' : '불가 — RANKS 마지막 값이 총 XP보다 큽니다');
console.log('챕터 경계와 어긋난 랭크:', bad.length ? bad.join(', ') : '없음');
"
```
